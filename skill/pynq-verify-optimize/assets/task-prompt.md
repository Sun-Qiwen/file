# 可复用任务提示词

请使用本技能，分析并优化当前 PYNQ 项目。以下项目输入由当前工程提供，不能继承技能历史案例的数值：

- 当前基线、源码/构建入口、bit/HWH、工具版本、板卡与器件。
- 原始性能报告、输入/参数/黄金参考、输出比较规则、IP 与寄存器契约。
- 目标完整调用延迟、资源预算、必须保持的数值/模型/接口/并行度限制。
- 本次允许范围：只分析 / 本地实现 / 包含已授权实板；以用户当前指示为准。

先确认算法/模型、目标精度、数据布局和接口是否已有稳定方案。目标明确为 INT8 且量化方案尚未验证时，优先验证任务效果、整数参考和实现可行性，再围绕目标方案深入优化硬件；允许较宽累加和混合精度，不强制全部算子 INT8 化。已有稳定方案和已冻结数值规则时直接继承，不因本流程重新训练或量化。上游决策变化后，列出旧优化/证据的可继承、需适配和失效范围。

再从现有资料查明完整调用与硬件各阶段的计时边界，分清互斥阶段和重叠忙时。对主要开销给出证据、候选改动、预算收益、资源代价和最小验证。历史优化逐项确认已继承、未继承或需适配；不按 INT8、MAC 数量或某个局部阶段改善直接推断整帧收益。

发现明确可行且在授权范围内的改动后实际实现。保持原参考、量化/舍入/饱和规则；先局部验证，再将通过筛选的独立修改合并，统一完成综合、布局布线和全部使用方的回归。共享核检查跨应用交替和连续无 reset 调用。不要为每项小改动重复完整流程，也不要跳过最终联合回归。

资源与时序按目标器件、实际时钟集合及用户约定验收，不固定预留某个 Slice 数。核对 MAC 本体与量化/地址逻辑的 DSP 区别、实际 II、packed buffer/bank 供数能力，以及输出末块的排空和所有权。

资源优化按本包 references/resource-optimization.md 执行：从层次报告和实际原语定位，优先检查数组寄存器化、临时副本、地址/解包、位宽与控制集，再按根因选择映射或布局方法。改 bank 证明容量/端口/反馈/初始化，改同步控制证明逐拍状态，纯组合映射保护必要状态，改 Pblock 按真实 sites 与全时序验收。预算包括互连、缓存和计划集成的外设，不为压面积丢失已有性能优化或合法回退容量。

布线时观察冲突节点与未布通连接的收敛趋势。若多个可比迭代无明显改善，且拥塞/资源报告支持难以收敛，保存诊断并提前停止本次布线，先优化资源结构、布局或相关约束，再重新实现。不要仅凭早期峰值或固定节点阈值中断，也不要长期重复没有进展的布线尝试。

若包含已授权实板，核对统一 Overlay、bit/HWH 来源、register_map/地址、实际时钟及缓存同步，使用固定输入执行 A1/B/A2。保留全部有效慢样本；正确性、恢复身份或环境漂移不满足时，不宣称可靠加速。若仅本地工作，完成本地可验证内容并标明待板测，不连接设备。

最终交付简洁报告、最小源码改动、可恢复基线、工件身份和复现命令。列出采用、拒绝和待证的具体方案；整帧实测、局部实测和预算分别呈现。不要把一次失败当成整个方向不可行，也不要为了目标数字放宽容差、选择最好样本或改变计时边界。
