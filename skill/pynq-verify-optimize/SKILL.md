# PYNQ 验证与性能优化

把“运行正确”“硬件更快”“完整流程更快”“实际资源和时序可交付”分别证明。优先恢复已验证的数据搬运与复用能力，再考虑扩大并行度。项目专有模型、地址、时钟、板卡与数值规则放进适配器，不进入通用判定逻辑。

## 先读取足够的事实

按用户任务选取所需资料：当前可恢复基线、目标板与器件、PYNQ/工具版本、bit/HWH 来源、IP/寄存器与缓冲区契约、数值参考、原始计时样本、实际综合/布局布线报告。先查已有报告和源码；只追问会影响下一步判断的缺项，不要求重跑已充分证明的步骤。

分析请求交付诊断；实施请求推进到已授权的验证层级。用户只要求本地工作时，交付待上板候选。本技能不额外授权 Overlay 下载、设备复位、远程登录或历史文件清理，也不为已经授权的正常步骤反复请求确认。

## 先稳定上游方案，再做深度优化

优先验证并稳定会影响后续实现的算法/模型、目标数值精度、数据布局和接口契约。神经网络项目若明确采用 INT8，应尽早验证量化后的任务效果、整数参考与实现可行性，再围绕目标方案深入优化存储、并行计算和物理实现；通常无需先把完整 FP32 版本在 PL 上深度优化一遍。允许较宽累加和混合精度，不将“所有算子 INT8 化”设为优化前提。

已有方案和证据充分时直接继承，不为执行本技能重新训练、重新量化或改变已冻结的数值规则。上游决策变化后，逐项判断旧优化与证据是可继承、需适配还是已失效；保留可复用的方法、参考和测试框架，重新验证受影响的打包、bank、调度、接口与物理实现。具体顺序和复用边界见 [工作顺序与变更影响](references/workflow.md)。

## 决策工作流

1. **固定比较对象。** 记录应用、软件与硬件版本、输入/权重/参考指纹、计时边界和实际时钟。多网络共享同一核时，把各网络与交替调用列入契约；某些卷积为 INT8 不等于整个应用完全 INT8。
2. **建立可解释的时间账。** 先测完整调用，再分 PS 预处理、搬运/缓存同步、硬件、后处理；硬件内部按可观测阶段拆分。只有互斥时间区间才能相加，忙计数与嵌套函数时间不能直接相加。`cycles / clock_hz × 1000` 才是毫秒。记录计数器位宽、溢出与采样范围。
3. **按证据选候选。** 列出当前耗时、重复事务/计算、改动、收益预算、资源代价和最小验证。小阶段局部提速不能解释大幅整帧收益。历史 FP32 的 burst、输入复用、调度方式可作为候选；INT8 的打包、饱和、舍入、边界读改写与 bank 冲突必须重新核对。
4. **局部筛选后合并。** 先对改动做黄金参考、边界/保护区、调度 II 与资源检查；多个独立且通过局部检查的修改可以合并后统一综合、布局布线和全应用回归。保留能分别关闭的改动或清晰源码差异。合并失效时按依赖拆分定位，不每个小改动都重复完整流程，也不把未验证修改一起押到最终构建。
5. **核验实际实现。** 区分 HLS 估算、综合资源、实际 routed 占用；核对完整时钟集合、setup/hold/pulse、约束覆盖、route 与 DRC。若冲突节点持续居高、多个可比迭代无明显下降，且拥塞或资源报告支持难以收敛，应保存诊断并提前停止本次布线，先优化资源结构、布局与相关约束，再重新实现。停止依据采用收敛趋势与当前设计证据，不套用固定节点数或仅凭早期峰值中断。具体处理见 [布线持续拥塞时的处理](references/workflow.md)。LUT 少不保证 Slice 少，总 DSP 不等于 MAC 数。资源预留来自当前项目；不继承案例里的固定预留值或器件上限。
6. **验证 PYNQ 运行契约。** 使用 [运行与接口约定](references/pynq-runtime.md)。bit/HWH 哈希相符只证明文件身份，配对需构建来源与接口证据。统一 Overlay 的加载所有权，多个驱动共享同一对象；不能为切换子模块重复下载另一个完整 bit。缓冲区由实际硬件访问状态决定生命周期。
7. **形成分层结论。** 已授权实板时，同输入、同边界、可比环境做 A1→B→A2；保留预热及全部有效慢样本，检查 A2 是否恢复同一基线。先判正确性与环境漂移，再报告平均值、中位数、分布和更快 A 的保守收益。当前测量不能证明全局最优、任意输入收益或其他板卡已验证。

## 何时读取其他材料

- PYNQ Overlay、register_map、缓存和超时问题：读 [运行与接口约定](references/pynq-runtime.md)。
- 需要合并优化、解释收益或诊断失败：读 [优化方法与故障定位](references/workflow.md)。
- 需要降低 LUT/FF/Slice/DSP/BRAM、修复装箱或缓解拥塞：读 [资源诊断与优化](references/resource-optimization.md)。按实际原语与根因选择存储、位宽、控制或物理方法；改变 bank 验证端口/反馈/II，改变控制证明状态，改变布局核对真实站点与完整时序。方法由三份旧技能提炼，见 [来源](references/resource-sources.md)。
- 需要执行离线检查：读 [工具与数据格式](references/tools.md)，使用 `scripts/evidence.py`。工具不连接板卡、不加载 Overlay、不启动综合。
- 需要检查现有 Vivado 资源/时序报告，或统计 DCP 站点、采集 PYNQ 状态：读 [资源与状态工具](references/resource-tools.md)。报告解析有明确版本/架构边界；站点工具需 Vivado，状态工具需在获授权的目标板执行，均不自动启动硬件任务。读取哪种资料就只运行对应工具。
- 需要更多既有资源案例、测试平台负例和运行失败经验：读 [历史案例与失败经验](references/legacy-cases.md)。历史验证与本次工具测试分开解释。
- 需要面向新项目执行：复制 [项目契约](assets/project-contract.json) 并填写真实值，使用 [任务提示词](assets/task-prompt.md)。契约中的 null 表示未知，不能当零或默认通过。
- 需要直接复用专项任务或报告：按 [提示词目录](prompts/README.md) 选当前阶段，填写 [配套模板](assets/templates/README.md)。只读取当前任务所需模板，不机械执行全部阶段。
- 需要独立于原题目的代码案例：使用 [向量加法 HLS IP 骨架](examples/vector_add_hls/README.md)。其原生 C++ 验证与 Tcl 替身检查不构成 RTL、时序或实板证明；目标器件和板级系统由使用方适配。
- 需要赛事引用与历史收益：读 [来源、案例与验证边界](references/evidence.md)；案例数据不成为新项目的固定要求。
- 整理比赛技能材料时，按 [交付对应与边界](references/submission.md) 说明复用方式，不把技能摘要替代完整工程与真实协作记录。

## 最小交付

交付当前版本与输入身份、已测时间账、采用/拒绝/待证的具体改动、相同阶段资源及最终时序、正确性范围、原始样本与复现命令。所有输出标明“本地检查 / 本地实现 / 实板验证”的证据层级。单个失败分支不推导整个方向无效；预测收益、局部收益和实测完整调用收益分别呈现。
