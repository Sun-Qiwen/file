# 资源诊断、结构优化与物理实现

从 `amd-fpga-resource-audit`、`amd-fpga-slice-optimization`、`pynq-slice-compaction` 三份既有技能去重提炼。适用于 AMD HLS/RTL 与 PYNQ Overlay 中资源紧张、装箱失败或持续拥塞的设计；参数、约束、板卡及访问模式由当前工程提供。来源与许可见 [整合来源](resource-sources.md)。

按需要阅读：先用“诊断与预算”和“排查表”选根因，再读相应的存储、算术、控制或物理章节，最后按“验证与继续条件”验收。无需每次对所有类别做完整审计。

## 1. 诊断与完整系统预算

先保存可恢复基线及源码、参数、约束、生成 IP、输入 DCP 的身份。记录器件完整型号、架构、工具版本、全部时钟、允许的精度/并行度/周期变化和可接受资源交换。功能与性能契约没有允许改变时，不靠减少工作量、MAC、频率或精度满足面积目标。

从完整系统到大模块，再到实际原语/端口/信号定位。区分 HLS 估算、综合网表、placed 与 routed 结果；父层次包含子层次，不能重复累加。逻辑数组容量、RTL 声明数量和实际物理 FF 数是三个不同指标。报告中缺失的值保持未知。

资源预算覆盖计算核、AXI 互连与转换、数据和参数缓存、统计逻辑、时钟/复位、计划集成的显示或其他外设。预留量来自最终系统需求和实现余量，不复制旧案例的固定 Slice 数。单模块 OOC 结果可用于预算，不能直接相加当作最终系统占用；综合共享、裁剪和布局打包会改变结果。

先区分四类根因：

|现象|优先取证|优化方向|
|---|---|---|
|LUT/FF/DSP/BRAM 本身超限|层次利用率、实际 RAM/算术实例、临时副本|源码与存储/算术结构|
|总量似乎能放下却装箱失败|控制集、进位链、SRL/LUTRAM、局部区域与硬核约束|合法打包、控制结构与布局|
|全局尚有空位但局部拥塞|拥塞位置、连接密度、高扇出、资源分布与 Pblock|减少热点连接或放宽/调整布局|
|面积降低但 II/时序恶化|实际调度、端口冲突、反馈路径、setup/hold|重新平衡资源、吞吐与物理空间|

## 2. 按实际占用排序的排查表

|对象|常见浪费或可调结构|实施前必须查明|
|---|---|---|
|小数组与累加器|complete partition、寄存器副本、动态索引选择器；评估 LUTRAM/BRAM|每拍读写、bank 映射、初始化与反馈距离|
|临时缓存与中转|拷贝、重复缓冲、清零；评估直接写最终 tile 或分时复用|存活区间、并发访问、别名、尾块及排空|
|位宽和参数表|宽计数器/地址、重复系数读取、零散小表|全合法范围、符号扩展、舍入/饱和与更新语义|
|bank 与地址计算|宽除余、动态 bank 选择、对齐/解包器|合法地址映射、原语分配、总容量、端口与 II|
|控制集|零碎 CE/reset、每元素控制、过多低负载组|逐拍状态、优先级、INIT、时钟与同步性|
|算术与流水|重复转换、地址乘法、无意复制；核对可共享运算|数据依赖、真实并发需求、量化与累加路径|
|AXI 与监测|outstanding/响应缓冲、宽接口转换、重复统计|最坏事务、背压、协议合法性及完成时排空|
|ROM 与常量|过宽系数、重复常量、可合并的同时读取字段|实际 ROM 推断、所有合法索引、解码代价与延迟|
|物理空间|过紧区域、分散摆放、MUXF/进位链约束|真实 sites、时序余量、局部拥塞与架构支持|

资源占用大也可能是维持吞吐和合法输入范围的必要代价。每项写明“采用 / 保留 / 拒绝 / 待证”及原因，不要求所有类别都做修改。

## 3. 存储优化：从访问证明到实际 RAM

先列出全部同拍访问，包括 loader、计算、清零、尾组和存储阶段。对每个逻辑索引定义 `bank(index)`、`row(index)`、word 内位/字节位置，并完成以下检查：

1. 每个合法逻辑位置有唯一物理表示，容量和 padding 足够；不把越界取模回合法区。
2. 每拍每 bank 的读写次数符合所选单口/简单双口/真双口 RAM 的实际语义，包含同地址读写行为。
3. 同地址再次使用的反馈距离与真实读改写延迟一致；需要转发时应明确验证。不能用未经证明的 `DEPENDENCE false` 隐藏真实依赖。
4. 加载器和消费者使用同一布局；合并 word、尾字节 mask、RMW 和保护区正确。
5. 检查实际生成 RAM 原语与 HLS 调度 II，再验代表性 RTL。源码中的 `BIND_STORAGE` 或 `PIPELINE II=1` 不是实现成功证据。

**小例子：** 对 `int32 accum[8][16]`，若每拍访问全部 8 个通道和一组 4 个连续位置，可评估：

```text
bank = 4 * channel + (position % 4)
row  = position // 4
```

这是 32 bank × 4 row × 32 bit，总计 512 B。每拍各 bank 至多承担该组的一次读和一次写，但是否能实现目标 II，仍取决于真实反馈延迟和 RAM 模式。若改为每拍 8 个位置，原布局将增加每 bank 的访问需求，必须重算；32 bank 不是通用最优参数。

非 2 的幂 bank 可能带来除余与选择开销，改成 2 的幂也可能增加 padding、RAM 数量或连接。比较实际生成物；不能把原 `%5` 简单替换成 `&7` 而不重建合法映射。

## 4. 缓冲复用、容量与初始化

给缓冲区标明“生产完成→最后消费”的存活区间；只有不冲突的分时占用才能共享。dataflow、ping-pong 和异步搬运中的两个副本可能是维持吞吐所必需，不能仅凭内容相同删除。

删除中转时，证明最终 tile 所有有效元素在写回前已完成，保留外部写入顺序、尾块守卫和最后事务排空。当前模型用量小不能替代通用合法命令的峰值容量；缩深需同时检查正常路径和回退路径，以及是否真的跨过物理 RAM 配置边界。

可评估按首次使用初始化累加器，减少清零和控制开销；需要覆盖空组、未参与 lane、连续调用及首次使用前读。浮点原来执行的 `0 + x`、归约顺序及项目支持的特殊值语义必须保持，不能只按实数代数改写。valid/tag 方案还应计入比较器、清零、标签回绕与新增选择器成本。

## 5. 位宽、系数与算术

按完整合法输入和参数范围推导中间位宽，包含语言的有符号提升、负极值、溢出、饱和、ReLU、舍入及最终 clamp 顺序。采样最大值不能证明全域范围；两路分别舍入后相加也不能随意改为先相加再舍入。

同时消费的系数可尝试合并存储，以减少接口与选择逻辑，但保留参数位模式、读取调度和更新方式。常量传播需核对实际常量及配置范围，不以删除合法配置或修改模型参数制造收益。

将 DSP 按 MAC 本体、量化、地址、转换和其他数学核分别统计。DSP 总量降低不等于削减计算并行度，总量增加也不等于增加 MAC。共享算术、对齐器或解包器可能降低 LUT/DSP 却使 II 变差，应按新增周期和完整调用预算决定是否继续。

## 6. 控制集与状态保持

根据当前架构报告，按 clock、CE、set/reset、极性与负载检查控制集，优先定位大量低负载组的来源。同步控制可评估共享使能或将部分保持/清零条件放到数据路径，但需逐拍比较状态转移，保留 reset 优先级、同步性、极性、INIT、暂停和有效信号。

该方法不直接适用于异步复位、CDC、时钟门控或硬 IP 控制。新增反馈多路器可能增加 LUT、路径延迟和连接；控制集数量下降不能代替最终 Slice 改善。不要无证据地全局重映射 CE/reset 或全量拆解 MUXF。

源级存储/控制重构可以合法改变状态实现，依据功能与时序契约验证。若仅做组合面积重映射，则先识别并保护需要保留的 FF、锁存、SRL、RAM、DSP、处理系统及其他状态硬核，核对可见 INIT、时钟/极性和状态输出连接。不能只保护某一种 FF，也不对全部组合逻辑无差别加 `DONT_TOUCH`。不可见属性或加密内部保持未知，不声称全参数等价。

## 7. 紧凑布局、拥塞与真实站点

从同一个适用的映射检查点比较物理策略，避免把源码改变和布局改变的贡献混在一起。已有可用基线、装箱证据和时序余量时，可以小步评估合法区域或组合面积映射；拥塞热点则可能需要疏散。紧凑与疏散服务于不同根因，不应固定只收紧区域。

Pblock 使用目标器件合法的完整 CLB/站点范围，读取工具最终 `GRID_RANGES`，按真实 `get_sites` 集合去重计数；坐标矩形面积不能直接代表容量。分别报告：

```text
device_free   = device_sites - occupied_sites
unused_allowed = allowed_sites - occupied_inside_allowed
```

同时检查区外占用。硬预留不属于当前允许区的空位；设备还有空位并不代表当前区域有足够的 hold 修复与布线空间。跨器件时按实际资源名称和单位解释，不能把另一架构的 CLB 数直接当本器件 Slice 数。

`opt_design -resynth_area`、`place_design` 的策略及 `phys_opt_design` 选项只在本机 `help` 确认版本、器件和执行阶段支持后使用。保持流水契约时，顺序重综合、retiming 或改变流水的优化必须另行证明并符合当前授权；不能照搬旧网表 ECO、坐标或 directive。`CELL_BLOAT_FACTOR` 等布局调整不计作逻辑资源压缩。

冲突节点长期不收敛时，遵循 [布线持续拥塞处理规则](workflow.md)：保存诊断、提前结束本次无进展尝试，再按根因优化资源结构、布局或约束。仅有早期高峰不作为停止依据。

## 8. 验证与继续条件

|层级|保留的证据|不满足时|
|---|---|---|
|局部结构/数值|容量、端口、生命周期、位宽/状态证明；黄金参考、保护区与边界|修复具体错误，停止扩大构建|
|HLS/生成 RTL|实际 RAM、算术实例、II/延迟；背压、尾组、连续调用|量化资源/周期交换，拒绝不符合契约的候选|
|完整综合/布局|同阶段资源、控制集、实际原语与约束|定位容量、装箱或约束根因|
|完整路由|routed 资源、setup/hold/pulse、约束覆盖、全部应布通网络与必要 DRC|保持待验证，不因已写出 bit 就验收|
|应用/实板（授权范围内）|所有共享核使用方、原参考/容差、相同边界 A/B/A|保留原始失败与慢样本，恢复约定基线|

多个独立候选先局部筛选再合并完整实现。HLS/RTL 源改变须有对应新生成物；纯物理变化可复用来源和约束适用性已确认的检查点；只改 PS 时通常无需重新布线。不要重复无关长流程，也不能沿用失效的旧证明。

检查器本身也需可信：actual 与 expected 都为 X/未知不能视为一致，参考数组要覆盖完整被访问范围；用注入错误证明测试确实会拒绝。工具退出码与明确失败/PASS 标记结合检查，不能仅凭 exit=0 判断仿真通过。

## 9. 最小资源结果表

每个候选记录：模块 → 报告阶段/身份 → 实际占用 → 根因证据 → 修改 → 所需证明 → 局部结果 → 采用/保留/拒绝/待证。汇总至少含：

- 器件/架构、工具、源/约束/生成物身份与比较阶段。
- LUT、FF、控制集、DSP 分类、BRAM 单位及实际 Slice/CLB。
- 允许区、硬预留、区内空位和区外占用。
- 各时钟、II/周期、WNS/TNS/WHS/THS、pulse、约束覆盖、route 与 DRC。
- 功能覆盖、应用性能证据、未覆盖范围与复现入口。

新资源方法不自动带来固定降幅。节省的 LUT/FF、routed Slice 和整帧耗时分别报告；历史案例及本次文档整合不能冒充新工程的实现或板测结果。
