# 来源、案例与验证边界

本技能从本队围绕 PYNQ 加速器的长期分析、提示词迭代、优化与验收材料中提炼。通用部分只保留跨应用的判断方法；模型、版本号和特定器件指标仅在本案例页出现，不是其他团队的运行依赖。

## 从实际观察提炼的规则

|历史观察/失败|提炼后的通用方法|
|---|---|
|整网 INT8 可运行，但旧版连续写回、复用等效率没有自动继承|从实际事务和调度核对历史优化，不把位宽缩小当作完整架构优化|
|Elementwise 包含不同重标定/直拷贝/查表路径，整体收益与预期不符|先分解算子与输入形态的耗时，再选择最值得改的一项|
|用户要求减少反复布线、仿真和测试开销|独立改动先做局部证据筛选，再合并做统一完整实现和回归|
|共享加速核同时执行两个应用，个别阶段仍保留浮点数学|所有使用方与交替调用回归；按运算阶段说明精度，避免“全部 INT8”的误称|
|packed/unpack、child 调度和 bank 改写出现 II 恶化|实际调度端口与 II 是早期淘汰依据，先量化影响再决定是否完整构建|
|缺失最后 stripe 的守卫，最终输出相同但有非法内部消费|检查真实访问所有权、生产/消费及排空，而不只比较最终数组|
|LUT、FF、Slice 变化不同，DSP 增加不等于卷积 MAC 增加|按实现阶段和原语层级核对资源，区分算法/映射/布局贡献|
|PS 预处理改写产生显著收益，但不等于同样整帧节省|验证逐字节数值、stride 与所有权，再测同边界完整调用|
|推理 bit 与原 HDMI bit 属于不同完整 Overlay|统一硬件集成及软件加载所有权，旧推理计时不冒充新显示链路体验|

前几项为多轮协作中的经验；下面的量化例子有本包冻结的报告副本。凡未附独立量化材料的经验，仅作为工作流来源，不声称单项加速数字。

## 案例一：联合优化与完整调用验证

来源：[历史 fc70 验收报告副本](evidence/fc70_report.md)，原文 SHA 和来源见 [source_identity.json](evidence/source_identity.json)。本次只读取并封存既有报告，没有重跑其综合、RTL 或实板实验。

环境为 PYNQ-Z2 / XC7Z020、100 MHz、CPU 650 MHz。报告记载同 boot、每组 1 次预热与 10 次正式样本：

|指标|A1|B|A2|
|---|---:|---:|---:|
|完整 Pipeline 均值 ms|1238.342|899.991|1230.935|
|候选同次调用硬件 / 核外 ms|—|805.406 / 94.585|—|

相对两 A 均值约省 334.647 ms（27.10%），相对更快 A 约省 330.944 ms。联合改动涉及输入复用、解包、精确量化写回、控制、Elementwise 和 PS 预处理；不能把各项局部最好收益相加，或将全部改进归于某一个方向。

该候选保持共享 64 路 INT8 卷积 MAC，routed Slice 13217/13300、DSP 212、BRAM36 等效 117.5；WNS +0.151 ns、WHS +0.010 ns。这里是单个案例的最终资源，不是技能要求其他板卡遵守的预算。

报告还记录：shared alignment 因 II2 预算净慢 54.319 ms 被排除；mac child 因 II2 新增预算 214.335 ms、超过可省排空时间被排除；缺末 stripe 守卫的分支捕获 288 次非法内部读取。它们支持“先局部筛选再统一实现”的价值，不能推导相关整个优化方向不存在更优实现。

## 案例二：资源收益与性能归因分开

来源：[历史紧凑布局案例副本](evidence/slice_case.md)，保留该来源的 [MIT 许可](evidence/slice_case_license.txt)。同源 cr64→cp65 案例中，routed Slice 13253→12400，约减少 6.4363%；LUT 42374→41932、DSP 与 BRAM 不变。该案例没有每一步独立布线消融，不能精确拆分映射和布局的贡献。

另一个 rz63→cp65→rz63 的应用性能对照包含 Concat 算法改动，其时间收益不能全部归因于物理布局。技能据此要求同阶段比较并拆开不同实验基线。

## 本包本次验证范围

新脚本的负例测试、向量加法演示与格式检查结果见 [验证记录](../validation/report.md)。向量加法不依赖本队网络，证明工具输入可以替换；合成 A/B/A 与假工件只验证逻辑，不能证明另一块实体板的性能或可加载性。

本次没有连接板卡、没有重置设备、没有运行 Vivado，没有新增跨板实测，也未进行独立代理行为压力测试。历史实板报告与本次离线验证分别保留，避免把旧成果当成新脚本验证成果。

## 向陌生项目迁移需要替换什么

三份旧技能的补充案例、原始结果和验证摘要现已合并保留，见 [历史案例与失败经验](legacy-cases.md)；新增资源工具的本次测试范围见 [资源与状态工具](resource-tools.md)。

1. 核、输入、参考函数、输出形状与容差；工具核心不改。
2. 器件/工具/PYNQ 版本、实际时钟、兼容 bit/HWH 与项目适配器；原硬件文件不能跨器件复用。
3. 性能边界、所有共享核使用方、资源预算与验收门槛；不继承 100 MHz、64 MAC 或任何固定预留值。
4. 如果 IP 控制协议、数据布局或缓存一致性属性改变，重新验证对应运行契约；跨平台 API/寄存器兼容性不由离线工具保证。
