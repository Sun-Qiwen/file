# 优化方法与故障定位

## 先回答四个不同的问题

|问题|需要的证据|不能代替它的证据|
|---|---|---|
|输出是否正确|冻结参考、数值规则、全部相关输出和边界测试|预测类别相同、只看一张图|
|硬件是否更快|相同调用与时钟下的实际硬件计时|HLS 理论吞吐、单层最好值|
|用户实际是否更快|相同起止边界的完整应用调用|把独立最短阶段拼成一帧|
|是否可交付|真实资源、全部时钟时序、完整路由/DRC、对应软件与工件|综合成功、成功写出 bit|

## 工作顺序与变更影响

把会引发下游重做的决策放到前面验证：算法/模型与输入规格 → 数值方案 → 数据布局、接口和 PS/PL 分工 → 存储/并行结构 → 深度性能与物理优化。方案之间允许有证据的小规模往返试验，不要求所有参数一次确定；避免在明显尚未稳定的上游方案上投入大量专用实现和反复完整布线。

1. **建立功能与效果基线。** 固定输入、预处理、输出定义和任务验收指标，保留参考实现。神经网络通常可先在 PC 上使用 FP32 模型确认任务效果，不必先完成高性能 FP32 PL 实现。
2. **尽早验证目标数值方案。** 若目标为 INT8，先检查量化后的任务效果，再明确尺度、符号、累加位宽、舍入、饱和、转换边界和整数参考。硬件与整数参考一致不能替代模型效果验收。允许部分运算保留浮点或其他精度；若精度或收益不满足要求，应在授权范围内调整方案，再进入大规模专用优化。
3. **联合确定数据流与硬件结构。** 围绕目标数值方案检查 PS/PL 分工、数据布局、packed 格式、接口、缓存、bank、并行度与完整系统资源预算。用小规模综合/调度和必要的物理试验排除明显不可行选项；位宽缩小并不自动保证供数、存储或吞吐改善。
4. **跑通目标方案，再按实际瓶颈优化。** 先建立可验证的完整调用基线，覆盖共享核的全部使用方，再安排访存、复用、计算、控制与 PS 优化。资源优化贯穿全过程；若资源已影响可实现性，应提前处理。
5. **方案稳定后集中实现与验收。** 局部通过的改动合并完成完整综合、布局布线、全应用回归及已授权的实板 A/B/A。已有证据只在身份和适用条件成立时继承；不为每个小改动重跑全部昂贵流程。

上述顺序用于规划新项目或有上游变化的阶段。已有稳定量化模型的性能任务直接使用当前方案，不重新校准、训练或改变模型；用户明确要求保持数值与模型时，以该限制为准。非神经网络项目同样先确定所需数值范围、精度和接口，无需引入“INT8 化”步骤。

每次上游变化建立一张最小继承表：旧成果 → 依赖的前提 → 本次是否改变 → 可继承/需适配/已失效 → 所需重新验证。

|已有成果|通常可复用的部分|必须重新检查的部分|
|---|---|---|
|burst、行复用、减少 DDR 往返|数据复用与连续访问的方法|打包宽度、对齐、尾部、容量、事务与实际收益|
|采集、计时和回归框架|流程和通用工具|输入/输出格式、计数含义、参考与比较规则|
|FP32 专用存储与计算实现|算法结构及已经证明的访问规律|目标精度的 bank/端口、算术流水、重标定与溢出规则|
|旧网表 ECO、Pblock 与时序结果|诊断方法和试验记录|新网表身份、器件/约束、合法站点、完整时序与路由|

保留 FP32 或其他原始参考以检查任务效果，同时维护目标数值方案的参考以核对实现。适配新方案时新增相应判据，不能通过放宽旧容差掩盖错误，也不能把所有旧优化都直接宣告失效而重写整套系统。

## 构建时间账

完整处理时间至少区分：输入取得/等待（如纳入边界）、PS 预处理、内存拷贝与同步、PL 调用、输出同步、PS 后处理/控制输出。摄像头读取、显示和控制稳定策略不在旧固定图测量范围时，不把旧数值称为“实时操作到显示延迟”。

PL 内拆分计算、输入/权重读取、解包、重标定、写回、控制以及其他算子。对每个计数器注明它记录的条件，以及与其他计数器能否重叠。不同命令/层的计数不得在未确认采样边界时累加。

局部阶段占总时间比例为 p，阶段加速 s 倍、其余与重叠关系不变时，总体加速预算为 `1 / (1 - p + p/s)`。把一个 10% 的阶段压缩 80%，理想整帧仅减少 8%。这是筛选预算，最终以完整调用测量为准。计算当前调度的下界时，写明哪些工作、带宽和重叠条件固定；不能称为设备或模型的绝对极限。

## 候选表与合并策略

资源紧张或装箱/布线问题使用 [资源诊断与优化](resource-optimization.md) 定位存储、算术、控制或物理根因，再将有证据的候选纳入下面的联合筛选。

每项用同一张表：

|开销及证据|候选改动|预算收益|资源与调度代价|局部验证|结果|
|---|---|---|---|---|---|
|来自当前样本/计数/事务|具体数据流或代码变化|ms 与假设|LUT/FF/BRAM/DSP/II/时序|最小能揭示错误的检查|采用、拒绝、待证及原因|

先消除有证据的重复工作：过碎写事务、重复加载/解包、冗余拷贝、每次重新初始化、不必要的中间落 DDR。若提出加倍 MAC，先检查持续供数、权重端口、累加、精确量化、写回和时序能否支撑；保留原并行版本作为可恢复基线，避免只保留尚未通过实现的候选。

迁移历史优化时，逐项记录“已继承 / 未继承 / 需重新实现”。例如 FP32 连续写回的方法可复用，但 INT8 四字节打包、未对齐首尾、读改写和逐通道重标定不能直接沿用原实现。输入复用也可能导致权重反复加载，必须核对两个方向的事务。

局部验证通过后再合并独立修改，集中跑昂贵的完整流程。重叠收益不相加；最终只将同一批完整调用的前后差算一次。若用户要求归因到单项，需要对应开关/消融证据，否则只能报告局部证据和联合收益。

## 布线持续拥塞时的处理

当冲突节点持续居高、未布通连接反复修复，多个可比迭代仍无明显下降，并有拥塞/资源报告支持难以收敛时，提前停止本次候选布线。保存已有日志、阶段统计、可用拥塞报告及可恢复检查点，使用工具支持的正常取消方式；不影响其他任务，也不把中断结果当成已完成实现。观察窗口根据设计规模、工具阶段和历史成功运行确定，不设跨器件通用的节点数或等待时长。

优先定位并缓解资源和布线压力：冗余或寄存器化存储、宽多路选择器、控制集碎片、高扇出控制、过度复制的并行数据通路、局部资源过密、过紧 Pblock，以及不合理的时钟/引脚/布局约束。按实际根因选择源码精简、存储映射、控制共享或布局调整，保持当前数值、接口与性能契约。资源优化以改善可布线性为目标；总 LUT 降低或进一步压紧布局本身不能证明拥塞减轻。

修改后先核对相关功能、II 与资源，再重新综合/布局/布线；纯物理调整可复用来源明确且适用的检查点。若节点仍在稳定下降，可继续观察。单个阶段的高节点数不足以认定资源过满；若证据指向约束、布局或连接问题，应修复对应原因，不反复尝试相同布线配置。

## 改动类型决定验证范围

- **打包/搬运/缓存复用：** 测未对齐首尾、最大合法尺寸、非整 tile、stride、4KiB 边界、背压、别名、保护区、连续无 reset 调用；观察实际消费与所有权，不能仅看最终输出恰好相等。
- **量化/查表：** 保留有符号扩展、乘加位宽、舍入顺序、饱和与 -128 边界；不同分支先分别量化后相加，不自动等价于先相加再量化。
- **PS 拷贝/预处理：** 验证每字节输出、dtype/shape/stride、BGR/RGB/布局、裁剪坐标和数组别名生命周期；不能凭视觉相似接受。
- **共享核：** 所有使用方都回归。两个网络测试 A→B→A，以及不同输入、参数和无 reset 复用；重点看缓存和残留状态是否被错误共享。
- **仅物理优化：** 同源检查状态/接口/时钟约束保持，再看实际 routed Slice 与时序；不要把其中另一项算法改变的速度归因给布局紧凑。
- **显示/外设集成：** 检查地址冲突、时钟/复位、CDC、引脚与新资源；推理核没变也不等于系统可以直接用旧 bit。确认软件不会再次下载一个仅含推理核的 Overlay。

## 常见失败与排查顺序

|现象|先确认|下一步|
|---|---|---|
|INT8 比 FP32 慢|执行入口与计时边界、是否同一数据流|对比 burst、缓存复用、实际 II 和量化写回；不按位宽推断速度|
|Elementwise 改进远低于预期|每种算子的占比、是否仍有重标定/回退|按 Add/Concat/Sigmoid 等拆分，核对搬运与 LUT 初始化占比|
|加宽并行度后变慢|实际 II、端口冲突、打包选择器和排空|先排除 II 恶化，再决定是否值得完整实现|
|LUT 降低但 Slice 仍满|真实站点、控制集、FF/进位链打包|同阶段比较，必要时做有依据的布局实验|
|只有最后几个字节不一致|尾 tile/尾 stripe、写 strobe、排空条件|记录每次有效访问与所有权，检查越界/未初始化读取|
|输出有时是上一帧|缓存同步、完成语义、缓冲区生命周期|核对启动前后顺序及后续写事务，检查共享状态|
|DMA/核一直等不到完成|控制协议、状态与错误位、流式边界|确认是流式 DMA 还是 m_axi；在明确 idle 前保留内存所有者|
|仿真失败但输出看似正确|检查器采样时刻、有效消费条件、实际 mux/state|保留失败日志；修正检查器需独立证据，不修改 golden 掩盖错误|
|测试波动或复测变快|实际软件/bit/时钟、输入、预热、环境|保留慢样本，报告漂移；没有证据就不要归因给 OS|
|工具启动即失败|可执行文件路径、环境、权限、临时目录|区分工具没有启动与综合/设计失败；不无条件重复完整流程|

## 最终报告模板

1. **范围与身份：** 基线、候选、输入/参考、软件/硬件指纹、工具、器件、时钟及计时边界。
2. **结论与分层证据：** 正确性、本地实现、实板与完整应用各自状态；未执行项保持待验证。
3. **收益：** 全部有效样本 n/mean/median/min/max/std、A1/A2 漂移、相对两 A 均值和更快 A 的结果。
4. **归因：** 当前时间账、采用/拒绝/待证的具体方案；预算与局部结果不充当整帧实测。
5. **资源与风险：** 相同阶段的资源、实际 routed 时序/路由、退路、未覆盖输入和下一项有证据的工作。
6. **复现：** 工件、配置、命令、原始报告和样本路径。

已有证据足够时不重建大规模归档；做清理任务时另行核对当前基线、生成 IP、运行数据和报告的真实依赖。
