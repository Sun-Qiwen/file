# 已验证案例：cp65 → ac66

环境：PYNQ-Z2 / XC7Z020CLG400-1、Vivado/Vitis2025.2、100MHz、32路MAC、单共享卷积核与单共享CNN数学核。模型、参数、整数/浮点规则和原有优化保留。本节是技能的经验来源；下面的工程路径只是原始证据索引，不是迁移依赖。

## 采用的方法

- 动态小输入tile从完全寄存器化改32bank×4row×32bit LUTRAM，保持512B与MAC供数。实际生成存储和II验证，不以逻辑bit数直接冒充省下FF。
- 删除qbuf中转，量化直接写最终output_tile，保持完整有效写入、顺序及后续DDR store；bias/mult成对放8×64 LUTRAM。
- 精确Q30 floor/remainder式替代宽绝对值，保留int32 bias饱和、ReLU、全uint32乘数、半值远离零和最终clamp；259720组数值核验。
- CNN三组16项数组LUTRAM化，按首次使用初始化，首次仍执行原`0.f+x`，短组未参与lane归约视为0，保留FP32顺序与算子配置。
- 全部7条Add使用每命令重建查表及packed小块读写；卷积复用同一原始缓存的完整行。这两项也改变访存与逻辑，最终性能不能当作资源压缩一项的独立收益。
- 保留原来支持的通用容量和共享数学核，不为压面积减少MAC、降频或改变精度。AXI outstanding等项证据不足，保留。

## 归因、失败和修正

|11000紧区placed只剩17个区内site，hold为负|不能接受；恢复12400允许/900硬预留后继续原placed点route，最终未增Slice且setup/hold通过|
|共享对齐器native正确但unpack II1→2|拒绝；逻辑共享不保证吞吐保持|
|fragment合并通过13824组局部证明及功能回归|因相对前一候选HLS FF+574/LUT+2206而拒绝，避免带宽收益换来过多逻辑|
|历史全局控制重映射/MUXF处理装箱更差|控制集低不保证Slice少；先定位来源再局部试验|
|CELL_BLOAT建议|只作为局部拥塞调节考虑，不记作逻辑压缩|
|新系统综合及e04导出在close/exit访问异常|保留原非零退出；前者同SHA DCP经CRC及独立重开核验后有界恢复，后者e05仅重导同一合格routed DCP并正常退出。不能把“文件已存在”当PASS|
|板上原实时程序占用硬件|走已有正常stop，等当前调用完成再释放/恢复；正式板测后重启原程序，CMA不足的首次启动失败保留，空闲时沿用文件缓存恢复后再启动|

## 正确性与实板效果

局部27卷积+45 Add+90 CNN、10项冻结实际卷积、32项实际生成RTL通过；统一native230条+37长尾通过。230条采集及审核后因Windows硬链接权限中断，仅续37长尾，保留失败；该native历史运行没有DLL起跑前哈希，只核验当前身份和此前文件时间，没有伪造追溯证明。

正式实板是同boot的cp65→ac66→cp65，各主要配置1预热+10有效，共530条。50 EW、90 CNN中间、完整输出/arena/保护区、计数及身份审核通过，原始有效慢样本全部保留。

本案例实测了一块板、一个项目，没有第二块板或其他题目的完整实测；新技能离线应用测试与本项目硬件验证是两件事。供应商opaque内部未独立解密或形式证明。正式候选接受后板上恢复的是原CP65实时程序，新版没有隐式替换实时默认部署。
